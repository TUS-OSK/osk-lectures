# 実践編：Git と GitHub の使い方

この資料では、日々の開発でよく使う Git の操作方法を解説します。

---

## 📁 リポジトリの作成と連携

新しくプロジェクトを始めるには、**「GitHub で空のリポジトリを作ってから PC にコピーする」**方法が最も簡単でオススメです。

### 1. GitHub でリポジトリを作る
1.  GitHub のトップページから **New** ボタン（緑色）をクリックします。
2.  **Repository name** を入力し、**Public** か **Private** を選択して **Create repository** をクリックします。

### 2. PC と連携する（2つのパターン）

リポジトリを作った後、PC で作業を始めるには以下のどちらかの方法を使います。

#### パターンA：新しく作り始める場合（オススメ✨）
GitHub 上にある空のリポジトリを自分の PC にまるごとダウンロード（コピー）します。

1. リポジトリページの **Code** ボタンから **SSH** の URL をコピーします。
2. ターミナルで以下を実行します：
```bash
git clone <コピーしたURL>
cd <フォルダ名>
```
これで連携済みのフォルダが作成されます。あとはファイルを作って作業するだけです！

> [!WARNING]
> **Private リポジトリは、HTTPS ではなく SSH でクローンする必要があります。**
> HTTPS でクローンしようとするとエラーになったり、現在は使えないパスワード入力を求められたりするため、必ず SSH の URL（`git@github.com:...` で始まるもの）を使ってください。

#### パターンB：すでに手元にファイルがある場合
すでに PC でコードを書き始めていて、それを後から GitHub に上げたい場合の手順です。

```bash
cd <作業中のフォルダ>
git init
git remote add origin git@github.com:ユーザー名/リポジトリ名.git
git branch -M main
```

## 🚀 基本の 3 ステップ：add, commit, push

コードを書いた後の保存の流れは、いつもこの 3 ステップです。

### ① `git add`（準備）
変更したファイルを「次のセーブに含めるよ」と登録します。
```bash
git add main.cpp    # 特定のファイルを登録
git add .           # 全ての変更ファイルを一括登録
```

### ② `git commit`（セーブ）
今の状態に名前を付けて、ローカルの履歴として確定させます。
```bash
git commit -m "A問題を解いた"
```

### ③ `git push`（アップロード）
自分の PC にある履歴を、GitHub（クラウド）に送信します。
```bash
git push origin main
```

## 📋 よく使うコマンド一覧

初心者がまず覚えるべき基本のコマンドです。

| コマンド | 意味 | タイミング |
| :--- | :--- | :--- |
| **`git status`** | 今の状況を確認 | 「あれ、今何してたっけ？」と思った時 |
| **`git log`** | 過去の履歴を見る | どんな変更をしてきたか確認したい時 |
| **`git pull`** | GitHub から最新を取得 | 他の人の変更を取り込みたい時 |
| **`git clone <URL>`** | リポジトリをコピー | GitHub のプロジェクトを自分の PC に持ってくる時 |

## 🕒 履歴（git log）の見方

`git log` を実行すると、過去のセーブ（コミット）履歴が表示されます。

```text
commit abc123def456... (HEAD -> main, origin/main)
Author: 自分の名前 <email@example.com>
Date:   Mon May 10 12:00:00 2026 +0900

    A問題を解いた
```

### 表示項目の意味
- **commit [長い文字列]**: **コミットハッシュ**。このセーブデータの固有 ID です。
- **(HEAD -> main, ...)**: `HEAD`（今自分がいる場所）などの情報です。
- **Author**: 誰がセーブしたか。
- **Date**: いつセーブしたか。
- **(空行の後)**: コミットメッセージ（セーブの内容）。

> [!TIP]
> 履歴が長すぎて画面が止まってしまったら、**`q` キー** を押すと元の画面に戻れます。
> また、`git log --oneline` と打つと、履歴が 1 行ずつコンパクトに表示されて見やすくなります。

> [!TIP]
> 各コマンドの詳細なオプションや、より高度なコマンド（stash, restore など）については、[04_git_dictionary.md](./04_git_dictionary.md) を参照してください。

## 💡 困ったときは？

- **コマンドが分からない**: `git --help` を打つか、AI に「Git で〇〇したいんだけどどうすればいい？」と聞いてみてください。
- **エラーが出た**: エラーメッセージをそのまま検索するか、先輩に相談しましょう！

Git は習うより慣れろです。まずは自分のコードを push してみることから始めましょう！
