# 逆引き：Git コマンド・オプション大辞典

この資料は、Git の様々なコマンドやオプションを網羅した辞書です。やりたいことからコマンドを探したり、オプションの詳細を確認したりするのに使ってください。

---

## ⚙️ 初期設定とリポジトリの作成

Git を使い始める時や、新しいプロジェクトを作成する時に使います。

| コマンド | 意味 |
| :--- | :--- |
| **`git config`** | Git の設定を確認・変更する |
| `git config --global user.name "名前"` | 自分の名前を登録する（初回のみ） |
| `git config --global user.email "メール"` | メールアドレスを登録する（初回のみ） |
| `git config --list` | 現在の設定一覧を表示する |
| **`git init`** | 今いるフォルダを Git リポジトリにする |
| **`git clone [URL]`** | リモートリポジトリを自分の PC にコピーする |

## 📋 基本コマンド（詳細版）

日常的に使うコマンドの便利なオプション一覧です。

| コマンド | オプション | 意味・役割 |
| :--- | :--- | :--- |
| **`git status`** | (なし) | 現在の変更状況やステージングの状態を確認する |
| | `-s` | 短縮形式で表示する |
| **`git add`** | `.` | （カレントディレクトリ以下）すべての変更をステージングする |
| | `-u` | 削除されたファイルも含めてステージングする |
| | `-p` | ファイル内の一部（ハンク）だけを選択して登録する |
| **`git commit`** | `-m "msg"` | メッセージを付けてコミットする |
| | `-am "msg"` | `add` と `commit` を同時に行う（追跡済みファイルのみ） |
| | `--amend` | 直前のコミットメッセージや内容を修正する |
| | `-v` | 変更内容を確認しながらコミットメッセージを書く |
| **`git push`** | `-u origin [名]` | 初回プッシュ時に追跡ブランチを設定する |
| | `-f` | **注意！** リモートをローカルの状態で強制上書きする |
| **`git pull`** | (なし) | リモートの変更を取り込んで現在のブランチに合体（マージ）する |
| **`git merge`** | `[名]` | 指定したブランチを今のブランチに合体させる |
| | `--abort` | 衝突（コンフリクト）した際にマージを中止して元に戻す |
| **`git log`** | `--oneline` | 履歴を 1 行ずつ表示する |
| | `-p` | 各コミットの差分（diff）を表示する |
| | `--graph --all` | すべてのブランチの分岐図を表示する |
| **`git branch`** | `-a` | リモートを含むすべてのブランチを表示する |
| | `-d [名]` | マージ済みのブランチを削除する |
| | `-D [名]` | 未マージでも強制的にブランチを削除する |
| **`git checkout`** | `-b [名]` | 新規ブランチ作成と移動を同時に行う |
| | `[名]` | 既存ブランチへの切り替え |
| **`git switch`** | `-c [名]` | 新規ブランチ作成と移動（`checkout -b` の現代版） |
| | `[名]` | 既存ブランチへの切り替え（`checkout` の現代版） |

## 🔍 覚えておきたい重要用語（ポインタなど）

Git を操作しているとよく出てくる、特別な名前や記法について解説します。

### 1. `HEAD`（ヘッド）
**「今、自分がいる場所」** を指す特別なポインタ（目印）です。
- ほとんどの場合、現在チェックアウトしているブランチの最新コミットを指しています。
- `git checkout` で別のブランチに移動すると、`HEAD` も一緒に移動します。

### 2. 過去のコミットを指す記号 (`^` と `~`)
「今より前の状態」を指したいときに使います。

| 記法 | 意味 |
| :--- | :--- |
| `HEAD` | 最新のコミット（今の場所） |
| `HEAD^` | **1 つ前**のコミット |
| `HEAD^^` | **2 つ前**のコミット |
| `HEAD~n` | **n 個前**のコミット（例：`HEAD~3` は 3 つ前） |

### 3. `origin`（オリジン）
**「リモートリポジトリ（GitHubなど）」** のデフォルトの名前です。
- `git remote add origin ...` で設定した、データの送信先（クラウド側）を指します。

### 4. `main` / `master`
リポジトリの **「メインとなるブランチ」** の名前です。
- 最近は `main` が一般的ですが、古いプロジェクトでは `master` と呼ばれていることもあります。

### 5. ステージングエリア (Index)
`git add` した後に、変更内容が一時的に保存される場所です。
- 「コミット（セーブ）する直前の、荷造り台」のようなイメージです。

### 6. `.gitignore`
Git の管理対象から除外したいファイルやフォルダを指定する設定ファイルです。
- パスワードなどの機密情報、ビルドで生成された一時ファイルなどを書き込みます。

## 🛠️ 知っておくと便利なコマンド

少し慣れてきたら使いたい、中級者向けのコマンドです。

### 1. ファイル操作と変更の追跡 (`mv`, `rm`, `blame`)
ファイルの移動や削除、誰がいつ変更したかの確認に使います。

| コマンド | 意味 |
| :--- | :--- |
| `git mv [旧] [新]` | ファイルの移動や名前変更を行い、その変更をステージングする |
| `git rm [ファイル]` | ファイルを削除し、その削除をステージングする |
| `git rm --cached [ファイル]` | ファイル自体は残し、Git の管理（追跡）対象からのみ外す |
| `git blame [ファイル]` | ファイルの各行を「誰がいつ、どのコミットで編集したか」表示する |

### 2. 変更の一時退避 (`git stash`)
「作業中だけど、別のブランチに急いで移動したい」という時に、今の変更を一旦脇に置いておけます。

| コマンド | 意味 |
| :--- | :--- |
| `git stash` | 今の変更を一時保存して、作業場を綺麗にする |
| `git stash list` | 保存されているスタッシュの一覧を見る |
| `git stash pop` | 最新の保存内容を復元し、一覧から消す |
| `git stash apply` | 復元だけして、一覧には残す |
| `git stash drop` | 最新の（または指定した）スタッシュを削除する |
| `git stash clear` | すべてのスタッシュを削除する |

### 3. 変更の取り消し・復元 (`git restore`)
「間違えて編集しちゃったから元に戻したい」という時に使います。

| コマンド | 意味 |
| :--- | :--- |
| `git restore [ファイル]` | 編集中のファイルを最後にコミットした状態に戻す |
| `git restore --staged [ファイル]` | `git add` したファイルを取り消す（ステージング解除） |

### 4. 同期と確認 (`git fetch`, `git diff`)

| コマンド | 意味 |
| :--- | :--- |
| `git fetch` | リモートの最新情報を確認だけする（勝手に合体しない） |
| `git diff` | まだ `add` していない変更箇所の差分を表示する |
| `git diff --cached` | `add` 済み（ステージング中）の変更の差分を表示する |
| `git diff main branch` | `main` と `branch` の差分を確認する |
| `git show [hash]` | 指定したコミット（[hash]）の詳細な変更内容を表示する |

### 5. 究極の取り消し (`git reset`)
**注意して使ってください。** コミットそのものを取り消します。

| コマンド | 意味 |
| :--- | :--- |
| `git reset --soft HEAD~1` | 直前のコミットを取り消すが、書いたコードは残す |
| `git reset --hard HEAD~1` | **注意！** 直前のコミットとコードの変更をすべて消去する |
| `git clean -n` | 追跡されていない削除対象のファイルを確認する |
| `git clean -f` | 追跡されていないファイルを強制的に削除する |
| `git reflog` | 最近行ったすべての操作履歴を表示する（消したコミットも探せる） |

### 6. 歴史の整列・移植 (`rebase`, `cherry-pick`)
複数のコミットをきれいにまとめたり、特定のコミットだけを別ブランチから持ってきたりする時に使います。

| コマンド | 意味 |
| :--- | :--- |
| `git rebase [名]` | 現在のブランチの基点を、指定したブランチの先端に移動する |
| `git rebase -i HEAD~n` | 直近 n 個のコミットをまとめたり（squash）、修正したりする |
| `git cherry-pick [hash]` | 別のブランチにある特定のコミット（[hash]）を、今のブランチに取り込む |
| `git revert [hash]` | 指定したコミットの変更を「打ち消す」新しいコミットを作る |

### 7. リモート操作とタグ (`remote`, `tag`)
複数人での開発や、特定の状態に名前を付ける時に使います。

| コマンド | 意味 |
| :--- | :--- |
| `git remote -v` | 登録されているリモートリポジトリの一覧を表示する |
| `git remote add [名] [URL]` | 新しいリモートリポジトリを登録する |
| `git push --force-with-lease` | 他人の変更を上書きしないよう安全に配慮した強制プッシュ |
| `git tag` | 現在のコミットにタグ（バージョン名など）を付ける |
| `git tag -a v1.0 -m "msg"` | 注釈付きタグを作成する |

## 💡 逆引き辞典

- **「最新の main を取り込みたい」**
  - `git pull origin main`
- **「直前のコミットメッセージを間違えた」**
  - `git commit --amend -m "正しいメッセージ"`
- **「間違えて add しちゃった」**
  - `git restore --staged [ファイル名]`
- **「今のブランチ名を変えたい」**
  - `git branch -m [新しい名前]`
- **「マージしようとしたけどやっぱりやめたい」**
  - `git merge --abort`
