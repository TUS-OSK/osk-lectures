# 嗜み編：良いコミットとドキュメント

Git は単なる保存ツールではなく、**「未来の自分やチームへの手紙」**でもあります。読みやすい履歴とドキュメントを作るためのコツを学びます。

---

## 📝 良いコミットメッセージの書き方

あとで履歴（`git log`）を見返した時に、「なぜこの変更をしたのか」が分かると非常に助かります。

### 1. プレフィックス（接頭辞）をつける
メッセージの冒頭に種類を書く習慣をつけると、一目で内容が分かります。

- `feat:` 新機能の追加
- `fix:` バグの修正
- `docs:` ドキュメント（READMEなど）の変更
- `refactor:` コードの整理（動作は変わらない）

**例**: `fix: A問題でゼロ除算が発生するバグを修正`

### 2. 「何をしたか」を具体的に書く
- ❌ `修正`（何を？）
- ❌ `update`（どう変わった？）
- ✅ `feat: ログイン機能を追加`

---

## 📄 README.md を書こう

リポジトリのトップページに表示される説明書です。これがあるだけで、プロジェクトの信頼性が一気に上がります。

### 書くべき項目の例
1. **概要**: これは何を作るプロジェクトか？
2. **使い方**: どうやって実行（コンパイル）するのか？
3. **開発環境**: 言語やライブラリのバージョンなど。

---

## ✍️ Markdown（マークダウン）の基本

資料作成や GitHub 上での議論で必須となる書き方です。

| 見た目 | 書き方 |
| :--- | :--- |
| # 見出し | `# タイトル` （#を増やすと小さくなる） |
| **太字** | `**太字**` |
| `コード` | \`コード\` |
| [リンク](https://...) | `[表示文字](URL)` |
| - リスト | `- 項目` |

### コードブロック
プログラムを書くときは、バッククォート 3 つで囲みます。
```cpp
// こう書くと
int main() { return 0; }
```
